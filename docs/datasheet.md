# Datasheet for Dataset: BBO Capstone Query and Evaluation History

This datasheet follows the structural framework defined in Mini-Lesson 21.1 to provide a transparent, reproducible, and credible record of the dataset generated during the Black-Box Optimisation (BBO) Challenge.

## 1. Motivation

### Which task helps this dataset to solve?
This dataset records the sequential evaluation history of an automated machine learning pipeline designed to locate the global maxima of eight distinct, hidden black-box target functions. It supports the task of sequential decision-making under epistemic uncertainty, specifically focusing on automated hyperparameter calibration, sample efficiency, and constraint-handling in engineering simulations.

### Who created it and why?
The initial baseline data points were officially generated and provided by the Imperial College London to establish the starting environment. All subsequent query points (comprising a total budget of 13 weekly submissions across Weeks 1 to 13, currently evaluated up to Round 11) were actively generated by the repository owner (@slilienstroem) using an automated BBO orchestration pipeline. The dataset was created to systematically track the evolution of query coordinates and their corresponding scalar performance signals to evaluate Gaussian Process (GP) surrogate models and Upper Confidence Bound (UCB) acquisition functions over successive rounds.

### Was it funded or supported by an organization?
The dataset development was supported by the academic infrastructure of the Imperial College London, utilizing personal local hardware for computation.

## 2. Composition

### What does it contain? What is the size and format?
The dataset contains continuous coordinate query vectors (inputs) and unnormalized scalar evaluation scores (outputs):
- **Inputs:** Bounded coordinate vectors in hypercubic unit space (2D to 8D), with coordinates between 0.000000 and 1.000000 formatted as hyphen-separated strings rounded to six decimals.
- **Outputs:** Single scalar objective performance signals with varying scales per task.
- **Format & Instances:** Stored as NumPy arrays (.npy) partitioned from function_1/ to function_8/. At the current milestone of Round 11, each function contains 21 historical point pairs (10 initial baseline samples plus 11 sequential queries), expanding to a total final budget of 23 data points upon completion of all 13 weekly submissions.
- **Dimensionality:** Ranging from 2D (Functions 1-2) up to 8D (Function 8).

### Are there gaps or missing data?
No technical gaps or corruption exist, though the combined `UCB` and `SVM` approach introduces strong confirmation bias, leaving large hypervolumes unexplored.

### Confidentiality and Intellectual Property
Contains no personal or sensitive information, nor protected university learning materials.

## 3. Collection Process

### How were the queries generated? Which strategy was applied?
The data collection was initiated by importing the 10 university baseline samples. The subsequent points were generated through an automated active learning loop executed locally. Coordinates were selected via a 65,000-point Monte Carlo sampling grid evaluated through a differentiated Upper Confidence Bound (`UCB`) acquisition policy. Promising spaces were restricted using a Soft-Margin Support Vector Classifier (`SVC`) trained on the top 75% of historical data, which drew non-linear boundary constraints to filter the sampling space.

### Over what timeframe?
The 10 baseline initialization points per function were provided in July 2026 (`Module 12`). The subsequent active query points were generated and collected sequentially from July 2026 to October 2026 (`Module 25`), restricted by a real-time server budget of exactly one evaluation query per function per week.

## 4. Preprocessing, Cleaning, and Labeling

### Have any transformations been applied?
Yes, specific transformations were applied during the collection loop to guide the surrogate models:
- **Sign Inversion Mapping:** In `Round 10`, an active inversion multiplier (`y_f = -y_f`) was applied to the feedback of `Function 4` to diagnose and correct suspected system-level signal anomalies.
- **Statistical Binarization:** For the geometric filter, raw scalar outputs were dynamically binarized into boolean labels (`0` or `1`) based on a rolling 75th percentile threshold to train the `SVM` classification boundary.
- **Data Safe Preservation:** Raw scalar evaluations are kept intact in local memory to ensure future compatibility with alternative acquisition frameworks.

## 5. Dataset Uses

### What are the intended and unintended uses?
- **Intended Use:** The dataset is strictly intended to fit Gaussian Process regressors, optimize anisotropic Automatic Relevance Determination (`ARD`) kernel length scales, and analyze sequential global optimization convergence behaviors under finite data budgets.
- **Unintended Use:** It is highly inappropriate for training generic deep neural networks or standard supervised classifiers from scratch, as the sample size is extremely sparse and severely biased toward high-performance local clusters due to active search optimization.

## 6. Distribution and Maintenance

### Where is the dataset available? What are the terms?
In accordance with the Capstone Project guidelines and data secrecy requirements, the raw numerical `.npy` arrays are excluded from public hosting using a `.gitignore` safeguard to preserve challenge integrity. However, the exact chronological metadata, parameter choices, and results tracking matrices are transparently published and version-controlled via this repository.

### Who maintains it?
The dataset is exclusively tracked, archived, and managed by the repository owner (@slilienstroem) using the Git version control system.
